§ interpretation                                                      ⟦⟧
═════════════════════════════════════════════════════════════════════════

entity-recall below 0.80 is expected when the CSL source uses :
  ₁ morpheme-suffix identifiers (verb'd , cmp't)   ← pattern, not entity
  ₂ glyph-only tokens (§ ⊗ → ≤ ⊑)                  ← no alpha chars
  ₃ abbreviated operators (@frame , .(prop))       ← regex-invisible

Both the CSL "entity" set and the EN "entity" set are generated by the
same IDENT_RE pattern. When the CSL file is *glyph-heavy* (C1, C3,
C7), only a subset of its concepts gets extracted as identifiers. The
EN paraphrase necessarily expands these glyphs into multi-word phrases,
pushing EN-entity count higher and thus recall lower.

I> low Jaccard-recall does NOT imply semantic mismatch ← it reflects
  glyph-expansion asymmetry inherent to the notation.
